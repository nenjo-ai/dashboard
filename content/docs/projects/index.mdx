# Projects

[Projects](/docs/introduction/building-blocks#projects) are the top-level containers for work in Nenjo. They group tasks, documents, settings, repository connections, and execution runs into a single, coherent workspace.

## What You'll Find Here

| Page | Description |
|------|-------------|
| [Tasks](./tasks) | Units of project work with assignment, dependencies, and lifecycle states |
| [Documents](./documents) | Encrypted and inlined project documents with knowledge graph structure |
| [Context](./context) | Project context and memory scoping for agent execution |
| [Settings](./settings) | Git sync configuration, metadata, and project-level configuration |

## Key Concepts

- **Isolation** — Projects provide isolated memory and execution boundaries for each body of work
- **Repository sync** — Connect projects to Git repositories for workspace-driven workflows with worktrees
- **Knowledge graph** — Organize documents using Domain, Entity, Policy, Taxonomy, Guide, and Reference kinds
- **Execution runs** — Process project tasks through stateful runs with dispatch and progress tracking

## Getting Started

1. Create a project with a clear name and purpose
2. Configure settings (models, memory profiles, repository connection)
3. Add documents to build the knowledge graph
4. Create tasks and execute them through routines or agent assignments

<Callout type="info">
Projects are the primary unit of organization and ownership in Nenjo. Every significant body of work lives inside a Project.
</Callout>
