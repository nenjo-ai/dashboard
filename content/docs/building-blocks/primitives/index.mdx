Primitives are the units you compose. They come in two families:

- **Context primitives** shape *what an agent knows*: [prompt context](/docs/building-blocks/primitives/template-variables), [context blocks](/docs/building-blocks/primitives/context-blocks), [knowledge graphs](/docs/building-blocks/primitives/knowledge-graphs), and [memory](/docs/building-blocks/primitives/memory).
- **Behavioral primitives** define *what an agent does*: [abilities](/docs/building-blocks/primitives/abilities), [domains](/docs/building-blocks/primitives/domains), and the [agents](/docs/building-blocks/primitives/agents) that assemble everything into a role.

The pages in this section run from the lowest-level context material up to agents, the composite that pulls it all together.

## The two families

| Family | Primitives | Job |
|--------|-----------|-----|
| **Context** | Prompt context, context blocks, knowledge graphs, memory | Supply what an agent should know — at design time and at runtime |
| **Behavioral** | Abilities, domains, agents | Define what an agent can do and how it behaves |

## How they stack

1. **Prompt context** separates static prompt references from runtime-owned session and turn data.
2. **Context blocks** package reusable static prompt guidance referenced by name.
3. **Knowledge graphs** hold explicit source material an agent searches and cites.
4. **Memory** carries learned, scoped context across runs.
5. **Abilities** add agent-invoked specialist behaviors.
6. **Domains** add user-activated modes.
7. **Agents** assemble the context and capability primitives into a behavioral role.

Once you have agents, [workflows](/docs/building-blocks/workflows) orchestrate several of them into repeatable processes.
