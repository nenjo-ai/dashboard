# MCP Integration

MCP servers give agents access to external tools. Nenjo stores MCP server configuration in the organization, then assigns servers to agents, abilities, or domains.

MCP configuration is metadata. It is protected by normal organization permissions, but it is not content-encrypted.

## MCP server fields

| Field | What it means |
|-------|---------------|
| `name` | Internal identifier |
| `display_name` | Human-friendly label |
| `description` | What the server provides |
| `transport` | `stdio` or `http` |
| `command` | Command for `stdio` servers |
| `args` | Arguments for `stdio` servers |
| `url` | Endpoint for `http` servers |
| `env_schema` | Declared environment variables the server expects |
| `category`, `tags`, `icon` | Organization and display metadata |

For `stdio` transport, a command is required. For `http` transport, a URL is required.

## Assignment

MCP servers are not automatically available to every agent. They become available through assignment:

- Assign a server to an agent for normal agent runs.
- Assign a server to an ability for that specialist execution.
- Assign a server to a domain for the active domain session.

At runtime, the worker combines the active agent, active domain, ability call, platform scopes, and MCP assignments to decide which tools are available.

## MCP and scopes

MCP assignment says which external server the runtime can use. Platform scopes still decide which Nenjo platform tools are available.

For example, assigning a GitHub MCP server may expose GitHub tools, while `projects:read` and `projects:write` determine which Nenjo project tools the agent can use.

## Transport examples

Local `stdio` server:

```yaml
name: filesystem
display_name: Filesystem
transport: stdio
command: npx
args:
  - -y
  - "@modelcontextprotocol/server-filesystem"
  - "{{ git.work_dir }}"
```

Remote `http` server:

```yaml
name: github
display_name: GitHub
transport: http
url: https://mcp.example.com/github
```

## Good practices

- Assign only the servers the agent or ability actually needs.
- Prefer environment schemas over hard-coded secrets in config.
- Keep high-risk tools behind explicit domains when the user should opt in.
- Pair MCP assignments with the smallest useful platform scopes.
