# MCP Integration

MCP (Model Context Protocol) servers provide external tool integrations that agents can use during execution.

## What MCP Provides

MCP servers expose external capabilities to agents:

- **File system operations** — Read, write, search files
- **Database queries** — Structured data access
- **API integrations** — External service connections
- **Custom tools** — Organization-specific capabilities

## MCP Server Types

| Type | Transport | Description |
|---|---|---|
| **stdio** | Local process | Runs as subprocess on same machine |
| **HTTP** | Remote URL | Connects to remote MCP servers |

## Core Fields

| Field | Description |
|---|---|
| `name` | Internal identifier |
| `path` | Unique reference path (e.g., `nenjo.mcp.filesystem`) |
| `display_name` | Human-readable name |
| `description` | What the MCP server provides |
| `transport` | `stdio` or `http` |
| `command` | Command to start the server (stdio) |
| `url` | Server URL (HTTP) |
| `env` | Environment variables |

## stdio Transport

Runs as a local subprocess:

```yaml
name: filesystem
path: nenjo.mcp.filesystem
display_name: File System
description: Read, write, and search files in the workspace.
transport: stdio
command: npx -y @modelcontextprotocol/server-filesystem /workspace
```

## HTTP Transport

Connects to remote servers:

```yaml
name: github
path: custom.mcp.github
display_name: GitHub
description: GitHub API integration for issues, PRs, and repos.
transport: http
url: https://mcp.example.com/github
```

## Agent Assignment

MCP servers are assigned to agents, not assumed available:

1. Agent defines which MCP servers it needs
2. Platform scopes control who can assign MCP servers
3. At runtime, the agent can call MCP tools

## MCP in Abilities and Domains

MCP servers can also be scoped to individual Abilities or Domains:

```yaml
# In an Ability
ability:
  name: code_review
  mcp_server_ids:
    - filesystem
    - github

# In a Domain
domain:
  name: compliance
  mcp_server_ids:
    - database
    - regulatory_api
```

## Security Considerations

- MCP server access is controlled by platform scopes
- Environment variables should not contain secrets directly
- Use secure credential management
- Audit logs track MCP tool invocations

## Common Patterns

### Filesystem MCP

For agents that work with repository files:

```yaml
name: filesystem
path: nenjo.mcp.filesystem
display_name: File System
description: Read and write files in the workspace.
transport: stdio
command: npx -y @modelcontextprotocol/server-filesystem {{ git.work_dir }}
```

### GitHub MCP

For agents that interact with GitHub:

```yaml
name: github
path: nenjo.mcp.github
display_name: GitHub
description: Issues, pull requests, and repository management.
transport: http
url: https://api.github.com
```

### Database MCP

For data access:

```yaml
name: database
path: custom.mcp.database
display_name: Database
description: Query and update project data.
transport: stdio
command: ./mcp-database-server
env:
  DATABASE_URL: $DATABASE_URL
```

## Tool Discovery

At runtime, available MCP tools are exposed via `{{ available_mcp_tools }}`:

```jinja
Available tools:
{{ available_mcp_tools }}
```

The agent can call MCP tools the same way it calls native platform tools.

## Best Practices

- Assign only the MCP servers the agent actually needs
- Use stdio for local operations
- Use HTTP for remote services
- Keep credential handling separate from MCP config
