# Memory

Nenjo agents can carry a **memory profile** inside their prompt configuration. The profile does not store memories by itself. It tells the memory system what the agent should care about when extracting, storing, and prioritizing memories.

The memory profile is part of the encrypted agent prompt configuration.

## Memory focus lists

| Focus list | What it means |
|------------|---------------|
| `core_focus` | Enduring themes this agent should care about across projects |
| `project_focus` | Project-specific topics that should rank higher for the active project |
| `shared_focus` | Knowledge that may be useful across agents or projects |

An empty memory profile is valid. The agent can still run; it simply has less guidance about what memories matter most.

## Template variables

Prompts can reference retrieved memory and the focus profile:

| Variable | Meaning |
|----------|---------|
| `{{ memories }}` | All retrieved memory scopes combined |
| `{{ memories.core }}` | Cross-project memories for the agent |
| `{{ memories.project }}` | Memories related to the active project |
| `{{ memories.shared }}` | Shared memories available across agents |
| `{{ memory_profile }}` | The full focus profile |
| `{{ memory_profile.core_focus }}` | Core focus list |
| `{{ memory_profile.project_focus }}` | Project focus list |
| `{{ memory_profile.shared_focus }}` | Shared focus list |

Use memory variables where remembered context helps the agent make a better decision. Do not include memory in every prompt just because it exists.

## Example profile

```yaml
memory_profile:
  core_focus:
    - user preferences
    - long-term engineering standards
  project_focus:
    - open decisions
    - task outcomes
    - acceptance criteria feedback
  shared_focus:
    - reusable implementation patterns
    - team conventions
```

## Good uses

- A coding agent remembers review feedback and team conventions.
- A project agent remembers decisions from previous tasks in the same project.
- A planning agent remembers recurring constraints and preferred tradeoffs.

## What to avoid

- Treating memory as a replacement for Library knowledge
- Storing sensitive one-off details in broad shared memory
- Putting project-specific facts in `core_focus`
- Overloading every agent with the same focus lists
