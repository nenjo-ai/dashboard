# Models

A **model** record tells Nenjo which provider and model string to use when an agent runs. Agents reference models by ID, so the same model record can be reused across agents.

Models are configuration metadata. They are not encrypted.

## Model fields

| Field | What it means |
|-------|---------------|
| `name` | Human-friendly name in the dashboard |
| `description` | Optional notes about when to use the model |
| `model_provider` | Provider identifier such as OpenAI, Anthropic, or another supported provider |
| `model` | Provider-specific model name |
| `base_url` | Optional custom endpoint for compatible providers |
| `temperature` | Sampling temperature, from `0` to `2` |
| `tags` | Labels used for organization and filtering |
| `project_id` | Optional project-specific model association |

The current model record does not store per-mode model switching, `top_p`, or `max_tokens` settings. If an agent needs a different model, assign a different model record to that agent.

## Assigning models to agents

Each agent has a `model_id`. Updating the model assignment changes which model that agent uses for future runs.

During onboarding, Nenjo asks for an AI provider and model, creates a model record, and assigns it to the default system agent. Additional agents can reuse that model or point to their own model records.

## Choosing a model

Use a stronger model for agents that need:

- Complex reasoning
- Long project context
- Careful code or document analysis
- Gate evaluation or architectural decisions

Use a faster or cheaper model for agents that need:

- Short chat responses
- Simple classification
- Routine formatting
- Low-risk background work

Temperature is the main behavior knob available in the current model record:

| Temperature | Best for |
|-------------|----------|
| `0` to `0.3` | Deterministic checks, gates, structured output |
| `0.4` to `0.8` | General project work and chat |
| `0.9` to `2` | Brainstorming or exploratory generation |
