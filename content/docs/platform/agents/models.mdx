# Models

Model assignment determines which AI model an agent uses for reasoning and generation.

## Model Selection Considerations

When selecting a model for an agent, consider:

| Factor | Considerations |
|---|---|
| **Task complexity** | Simple chat vs complex reasoning |
| **Latency requirements** | Real-time interaction vs background tasks |
| **Cost sensitivity** | Budget constraints per execution |
| **Capability needs** | Advanced reasoning vs fast responses |
| **Context length** | Amount of context the model can handle |

## Model Properties

Each model configuration includes:

| Property | Description |
|---|---|
| `model` | Model identifier (e.g., `claude-3-5-sonnet`) |
| `temperature` | Sampling temperature (0.0–1.0) |
| `max_tokens` | Maximum response length |
| `top_p` | Nucleus sampling threshold |

## Common Model Configurations

### Claude Haiku

Fast, cost-effective for simple tasks:

```yaml
model: claude-haiku-20240307
temperature: 0.7
max_tokens: 4096
```

Best for:
- Quick queries
- Simple classifications
- High-volume background tasks

### Claude Sonnet

Balanced capability and speed:

```yaml
model: claude-3-5-sonnet-20241022
temperature: 0.7
max_tokens: 8192
```

Best for:
- General purpose agents
- Chat interactions
- Standard implementation tasks

### Claude Opus

Highest capability for complex reasoning:

```yaml
model: claude-3-opus-20240229
temperature: 0.7
max_tokens: 16384
```

Best for:
- Complex architectural decisions
- Multi-step reasoning
- Gate evaluation

## Temperature Guidelines

| Temperature | Use Case |
|---|---|
| 0.0–0.3 | Deterministic outputs, gates, validation |
| 0.4–0.7 | General conversation and tasks |
| 0.8–1.0 | Creative generation, brainstorming |

## Context Window Considerations

Models have different context windows. Match your prompt complexity to the model's capacity:

| Model | Context Window |
|---|---|
| Haiku | 200K tokens |
| Sonnet | 200K tokens |
| Opus | 200K tokens |

For long-running agents or complex projects, ensure:
- Prompt templates are concise
- Memory profiles are focused
- Project documents use metadata summaries

## Model Switching

Agents can switch models based on runtime mode:

```yaml
model_configs:
  chat: claude-haiku-20240307
  task: claude-3-5-sonnet-20241022
  gate: claude-3-opus-20240229
```

This allows optimal resource allocation:
- Fast responses for simple chat
- Full context for task execution
- Deep reasoning for evaluation

## Best Practices

- Start with balanced models (Sonnet) and optimize if needed
- Use deterministic settings (low temperature) for gates
- Monitor token usage to control costs
- Match context window to task complexity
