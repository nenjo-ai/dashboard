Model selection is a critical configuration choice for agents. The model determines the agent's reasoning capabilities, speed, cost, and available context window.
## Model Selection Considerations
When choosing a model for an agent, consider:1. **Task complexity** — Simple tasks may not need the most capable models
2. **Context requirements** — Some tasks need larger context windows
3. **Latency tolerance** — Faster models for interactive use, slower for complex reasoning
4. **Cost sensitivity** — Balance capability with cost efficiency
5. **Specialization** — Some models excel at specific task types## Common Model Profiles
| Profile | Use Case | Example Models | Characteristics |
|---------|----------|----------------|-----------------|
| **Fast/Interactive** | Chat, quick lookups | claude-haiku, gpt-4o-mini | Low latency, lower cost |
| **Balanced** | General purpose | claude-sonnet, gpt-4o | Good capability/speed balance |
| **Capable** | Complex reasoning | claude-opus, gpt-4-turbo | Highest capability, higher cost |
| **Long Context** | Document-heavy tasks | claude-3-5-sonnet-200k | Large context windows |## Model Configuration
Each agent has a `model` field that specifies:```yaml
agent:  model: claude-sonnet-4-20250514
  # Optional: temperature, max_tokens, top_p settings  model_config:    temperature: 0.7    max_tokens: 4096    top_p: 0.9```## Best Practices1. **Start with balanced models** — Adjust based on observed performance
2. **Consider task-specific specialization** — Some tasks benefit from specific models
3. **Monitor costs** — Track model usage and adjust as needed
4. **Test with real workloads** — Benchmark with actual task patterns
5. **Keep fallback options** — Have backup models configured## Related Concepts
