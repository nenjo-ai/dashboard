# Context and Settings

Project settings hold configuration that belongs to the project rather than to a single task, agent, or document.

The dashboard exposes two important settings areas: **Project Context** and **Metadata**.

## Project context

Project context is a free-form text field stored in project settings as `context`.

Use it for high-level guidance that should apply across the project:

- Goals and non-goals
- Architecture notes
- Domain constraints
- Coding or writing conventions
- Important stakeholders or user groups
- Default assumptions agents should remember during project work

Keep project context readable. It should orient agents, not replace documents or task acceptance criteria.

## Project metadata

Project metadata is stored as custom key-value data under project settings.

Use metadata for compact values agents or integrations may need:

- Environment name
- Product area
- Customer or team label
- Release train
- External tracking IDs
- Repository or deployment hints that do not belong in a task

Metadata is not encrypted. Do not put secrets in project metadata.

## Settings and prompt context

When a project is part of an agent run, Nenjo builds project prompt context from the project manifest. Project variables include project identity and, when available, repository and document context.

Good project context gives agents broad orientation. Documents give agents durable reference material. Tasks give agents specific work.

## Permissions

Reading project context and settings requires `projects:read`. Updating them requires `projects:write`.

Agents should receive the smallest project scope that matches their job. A read-only research or review agent usually does not need `projects:write`; a planning or project-maintenance agent often does.
