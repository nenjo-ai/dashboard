# Tasks

Tasks are the work items inside a project. They give agents a concrete title, description, acceptance criteria, status, priority, type, and optional routine assignment.

The project Tasks tab lets you create tasks manually, filter by status, open task details, manage dependencies, and clear all tasks for a project.

## Task fields

| Field | Purpose |
|-------|---------|
| Title | Short human-readable description of the work |
| Description | Additional task detail, encrypted when stored through the dashboard |
| Acceptance criteria | Conditions the work should satisfy, encrypted when stored through the dashboard |
| Status | `open`, `ready`, `backlog`, `assigned`, `in_progress`, `done`, or `failed` |
| Priority | `low`, `medium`, `high`, or `critical` |
| Type | `bug`, `feature`, `task`, or `improvement` |
| Routine | Optional routine that should process the task |
| Assigned agent | Optional agent assignment |
| Dependencies | Links to tasks that must be considered before this task |

Task title, status, priority, type, tags, order, and assignment metadata are visible platform metadata. Task description and acceptance criteria are stored as org-encrypted content when the dashboard creates or updates them.

## Routines and tasks

A task can reference a routine. The routine describes how the work should move through agents, gates, councils, and terminal outcomes.

Use task routines when work should follow a repeatable process. For example, a feature task might move through implementation, review, testing, and a terminal success or failure path.

## Dependencies

Tasks can depend on other tasks. Dependencies are useful when agents need to understand sequencing or when one task should not be treated as isolated work.

Dependencies are project-scoped. They are managed through the task detail surface and stored separately from the task body.

## Agent tools

Agents with `projects:read` can receive read-oriented project tools such as listing project tasks and reading individual tasks. Agents with `projects:write` can receive mutation tools such as creating, updating, deleting, and starting project work.

Scopes add tool access; they do not make an agent automatically use the right tool. The agent prompt should still explain when task changes are appropriate.
