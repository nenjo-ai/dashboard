# Project Knowledge

Nenjo's current source-material surface is the **Library**, not a project-owned document table. A project can use Library knowledge, but the project resource itself should stay focused on work: tasks, settings, repository context, executions, and project-scoped memory.

Use this page as a bridge if you are coming from the older "project documents" mental model.

## Where source material belongs

Put source material in the Library when it is:

- Product or architecture reference material
- Policies, procedures, or compliance rules
- Domain glossaries, taxonomies, or classification guides
- Research notes or source-backed guidance
- Project-relevant documentation agents should search and read before answering

Library items are exposed as knowledge packs with document metadata, graph relationships, search, neighbor traversal, and full-content reads.

## What belongs in project settings

Use project context and metadata for compact orientation:

- Goals and non-goals
- Repository conventions
- Product area or environment labels
- Default assumptions for project work
- Short references to Library packs that should be consulted

Do not put long policies, full architecture docs, source material, or generated outputs into project context. Use Library knowledge for source material, memory for learned facts, and artifacts for saved outputs.

## Prompt pattern

Use `{{ project }}` for workspace context and `{{ lib.<pack_slug> }}` for Library knowledge discovery.

```jinja
Project:
{{ project }}

Knowledge index:
{{ lib.product_docs }}

Before answering policy or architecture questions, search the knowledge pack,
read the most relevant document, and cite the document title or selector used.
```

Knowledge indexes are discovery hints. They are not full source material. Agents should use `search_knowledge`, `list_knowledge_neighbors`, and `read_knowledge_doc` before making source-backed claims.

## Practical rule

If the content is a task, use project tasks. If it is learned context, use memory. If it is a saved output, use artifacts. If it is source material that should be searchable and citable, use the Library.
