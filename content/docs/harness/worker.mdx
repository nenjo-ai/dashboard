# Worker

The Nenjo Worker is a long-running service that executes platform-routed work. It maintains persistent connections via NATS, handles capability-based execution, and bridges SDK runtime with platform transport.

## Purpose

The Worker serves as the always-on execution layer for Nenjo:

- **Always-on execution**: Continuously available for platform-routed tasks and MCP calls
- **NATS transport**: Message bus communication with platform sessions and chat
- **Capability execution**: Runs ability-defined specialist modes on behalf of agents
- **Session management**: Maintains conversation state and memory across interactions

## Architecture

```
┌─────────────────┐     NATS      ┌─────────────────┐
│    Platform     │◄───────────►│     Worker      │
│  (chat/tasks)   │   messages   │  (always-on)   │
└─────────────────┘              └───────┬────────┘
                                          │
                                  ┌───────▼────────┐
                                  │   SDK Runtime  │
                                  │  (abilities) │
                                  └─────────────┘
```

### Components

| Component | Description |
|-----------|-------------|
| **NATS listener** | Subscribes to platform task and execution queues |
| **Session manager** | Maintains active conversation and memory state |
| **Ability executor** | Runs specialist modes (web-search, code-interpreter, etc.) |
| **SDK runtime** | Embeds Nenjo SDK for manifest loading and agent execution |
| **Status reporter** | Publishes worker health and capability availability |

## Configuration

### Basic Setup

```toml
# worker.toml
[worker]
id = "my-worker"
org_id = "org-123"

[nats]
url = "nats://localhost:4222"
queue = "nenjo.execution"

[capabilities]
enabled = ["web-search", "code-interpreter", "file-read"]

[security]
api_key = "nenjo_wk_xxx"
trusted = true
```

### Starting the Worker

```bash
# Start with config file
nenjo-worker serve --config worker.toml

# Start with specific capabilities
nenjo-worker serve --capabilities web-search,code-interpreter

# Start in development mode (hot reload)
nenjo-worker serve --dev
```

### verifying Status

```bash
# Check worker status
nenjo-worker status

# List available capabilities
nenjo-worker capabilities

# View active sessions
nenjo-worker sessions
```

## Capabilities

Capabilities define what the Worker can execute on behalf of the platform. They map to [abilities](/guide/abilities) defined in agent configurations.

### Built-in Capabilities

| Capability | Description | Requirements |
|------------|-------------|--------------|
| `web-search` | Search the web for information | Network access |
| `code-interpreter` | Execute code in sandbox | CPU/time limits |
| `file-read` | Read files from configured paths | Path allowlist |
| `file-write` | Write files to configured paths | Path allowlist |
| `http-request` | Make HTTP API calls | Domain allowlist |

### Custom Capabilities

Define custom abilities in manifest files:

```yaml
# ability-manifest.yaml
id: my-custom-ability
name: Custom Processor
description: Processes data using custom logic
entrypoint: my_crate::processor::run

runtime:
  timeout_ms: 30000
  memory_mb: 512

input:
  type: object
  properties:
    data:
      type: string
    options:
      type: object

output:
  type: object
  properties:
    result:
      type: string
```

## NATS Message Protocol

### Execution Request

```json
{
  "type": "execution.request",
  "id": "exec-123",
  "ability": "web-search",
  "agent_id": "my-agent",
  "input": {
    "query": "Rust async best practices"
  },
  "context": {
    "project_id": "proj-456",
    "session_id": "sess-789"
  }
}
```

### Execution Response

```json
{
  "type": "execution.response",
  "id": "exec-123",
  "status": "success",
  "output": {
    "results": [...]
  },
  "metadata": {
    "duration_ms": 250
  }
}
```

## Security

### API Key Authentication

Workers authenticate with platform using API keys:

```bash
# Generate worker API key
nenjo-cli worker create --name "prod-worker"

# Output:
# nenko_wk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### Trusted Workers

Mark workers as trusted to bypass certain restrictions:

```toml
[security]
trusted = true  # Bypasses path allowlists, timeouts
```

### Encryption

Workers can handle encrypted content when enrolled as trusted devices. See [platform scopes](/guide/scopes) for permission boundaries.

## Troubleshooting

### Worker Not Connecting

```bash
# Verify NATS connectivity
nenjo-worker diagnose --nats

# Common issues:
# - NATS server not running
# - Firewall blocking port 4222
# - Invalid API key
```

### Capability Not Available

```bash
# List enabled capabilities
nenjo-worker capabilities

# Add capability
nenjo-worker capability add web-search
```

### Task Timeout

```bash
# Check worker logs
nenjo-worker logs --follow

# Increase timeout in config
[worker]
timeout_ms = 60000
```
