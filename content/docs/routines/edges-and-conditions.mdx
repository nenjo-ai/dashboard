# Edges and Conditions

Edges are the arrows between routine steps. They decide where the routine goes after a step completes.

## Conditions

Nenjo stores three edge conditions:

| Condition | Meaning |
|-----------|---------|
| `always` | Follow this edge regardless of the previous result. |
| `on_pass` | Follow this edge when the previous step passed. |
| `on_fail` | Follow this edge when the previous step failed. |

In the editor, normal steps have one output handle and default to `always`. Gate and cron nodes have pass and fail handles, which map to `on_pass` and `on_fail`.

## Pass and fail results

Agent, gate, council, and cron steps all produce a result. That result includes whether the step passed, the output text, and structured verdict data when the agent used the verdict tool.

Routing uses the pass/fail value:

- A passing gate follows an `on_pass` edge when one exists.
- A failing gate follows an `on_fail` edge when one exists.
- A cron step can follow pass or fail routes the same way.
- A normal `always` edge can be used when the next step does not depend on the verdict.

## What happens when no edge matches

If a step finishes and no outgoing edge matches the result, the routine ends with the last step result. This can be useful for small routines, but most production graphs should use terminal and terminal fail steps so the end state is visible.

## Common patterns

| Pattern | Shape |
|---------|-------|
| Linear pipeline | Agent -> Gate -> Terminal |
| Review loop | Agent -> Gate fail -> Agent revision -> Gate |
| Explicit failure | Gate fail -> Terminal fail |
| Multi-agent review | Agent -> Council -> Gate -> Terminal |

Keep gates close to the work they evaluate. If a gate appears much later in the graph, it becomes harder to understand what it is judging.
