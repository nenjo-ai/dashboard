# Graph Validation

The routine editor saves the graph as a set of steps, edges, and entry step references. The backend validates that the saved graph points to real resources before it accepts the update.

## What is validated on save

Nenjo checks that:

- The routine belongs to the current organization.
- Each referenced council belongs to the same organization.
- Each referenced agent belongs to the same organization.
- Edge source and target references point to steps in the saved graph.
- An edge cannot point from a step to itself.
- Entry step references point to steps in the saved graph.
- Cron routine schedules parse when a schedule is present.
- Authored step types are `agent`, `council`, `gate`, `terminal`, and `terminal_fail`.
- Gate `on_fail` retry edges remain bounded by edge metadata or the runner default.

The save operation is transactional. Nenjo replaces the routine's stored steps and edges together, so a partial graph update is not left behind if saving fails.

## Entry steps

The editor stores trigger-to-step connections as `entry_steps` in routine metadata. Each entry is a stable step slug, not a database ID.

At runtime, Nenjo prefers those entry step slugs. If none are stored, the worker falls back to the first step with no incoming edge. If it still cannot determine one, it uses the lowest ordered step.

## Runtime guardrails

When a routine runs, the worker walks from step to step by following matching edges. Ordinary flow should be acyclic. The valid retry shape is a bounded gate failure loop: a gate `on_fail` edge can route back to an earlier step and use retry metadata.

That means a graph can contain review loops, but the gate owns the retry decision and the loop still needs a path to terminal success, terminal failure, or escalation after exhaustion.

## Practical checklist

Before relying on a routine, check that:

- The trigger node is connected to the intended first step.
- Gate nodes have both pass and fail paths when both outcomes matter.
- Every intentional success path reaches a terminal step.
- Every intentional rejection path reaches a terminal fail step or a clear recovery step.
- Agent and council references are still valid.
- Scheduled routines have a valid schedule before you start the loop.
