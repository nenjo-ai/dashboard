# Routines

A **routine** is a repeatable workflow. It describes what should happen, which agent or council should do each part, and how Nenjo should route the work when a step passes or fails.

Use a routine when a job has a real process: draft then review, inspect then approve, run a scheduled check, or route a failure back through another agent instead of leaving everything to one long chat.

## What a routine contains

| Part | What it does |
|------|--------------|
| Trigger | Decides how the routine starts. Current triggers are `task` and `cron`. |
| Steps | The boxes in the workflow graph: agent, council, gate, cron, terminal, or terminal failure. |
| Edges | The arrows between steps. Edges can always run, run on pass, or run on fail. |
| Entry steps | The step or steps connected from the trigger node. |
| Metadata | Routine settings such as a cron schedule and entry step IDs. |
| Project binding | Optional project context, mainly used by scheduled routines. |

Routines are organization resources. The API surface is controlled by `routines:read` and `routines:write`; councils used inside routines are controlled separately by `councils:read` and `councils:write`.

## Task routines

Task routines are built in the graph editor. They are meant for project work that should follow a known path.

A task routine usually starts at an agent step, moves through one or more gates, and ends at a terminal step. If a gate fails, the routine can route to a revision step, a council, or a failure terminal.

## Scheduled routines

Scheduled routines use the `cron` trigger. In the dashboard they appear under **Schedules**, where you can set an interval or cron expression, start or stop the loop, and inspect recent cycles.

Scheduled routines still have a graph. The schedule decides when the routine runs; the graph decides what happens during each run.

## Councils in routines

A council is a multi-agent collaboration group. Inside a routine, it behaves like one step with its own internal collaboration strategy.

Use a council when the work needs several perspectives, review, voting, decomposition, or synthesis. Use a normal agent step when one clear role is enough.

## How execution flows

When a routine runs, Nenjo finds the entry step, executes it, records the step result, and follows the first edge whose condition matches the result. The routine stops when it reaches a terminal step, reaches a terminal failure step, an agent step returns a failure verdict, or there is no matching outgoing edge.
